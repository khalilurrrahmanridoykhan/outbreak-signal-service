# Data provenance

This file says where every kind of data used by this project comes from, so that
nothing in the repository is mistaken for something it is not.

## In the repository today

The repository contains **no surveillance data**. Tests create a handful of
invented rows (for example an org unit called "Bo" with a made-up series) purely
to check database constraints. They do not describe real places or real counts.

## Sources

| Source | Used for | Nature | Licence and terms |
|---|---|---|---|
| Public DHIS2 demo instance (`play.dhis2.org/40`, resolving to `play.im.dhis2.org/stable-2-40-12` as of the Phase 2 spike) | Running the real sync (default configuration) and the opt-in `live` tests | "DHIS 2 Demo - Sierra Leone": demonstration data published by the DHIS2 project, specifically its **IDSR Weekly** dataset (Cholera, Malaria, Measles, Plague, Yellow fever). **Not real surveillance data** — see `docs/dhis2-spike.md` | Subject to the DHIS2 demo terms; used read-only; the instance resets nightly and its data window moves forward unpredictably (see the spike, section 4) |
| Synthetic series generator (planned, Phase 3) | Testing and evaluating detection algorithms | Generated: seasonal baseline plus Poisson noise plus a controlled injected outbreak. Fully reproducible from a documented random seed | Generated by this project, Apache-2.0 |

Credentials for the demo instance default to its own published, intentionally
public `admin`/`district` login (see `application.yml`); a real deployment
overrides every `outbreak.dhis2.*` setting with its own instance and
credentials, read from the environment and never committed.

## Refresh and reproducibility

- Synthetic data is regenerated from its seed; the seed is recorded next to every
  reported result.
- Data pulled from the demo instance is fetched on demand and is not committed to
  the repository (a developer's local database is gitignored, per `.gitignore`).
  Its provenance (instance URL, version, time of retrieval) is recorded with each
  sync run via the `fetched_at` column and the sync's own log line.

## What this project will never contain

Real patient records, case-level line lists, or data obtained from any real
health facility or programme. See [ETHICS.md](ETHICS.md).
